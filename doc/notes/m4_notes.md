# M4：球軌跡預測，從物理公式到事件驗證

整理日期：2026-11-16。對應已驗證的M4零旋／無摩擦基線，不代表實物標定或主動擊球完成。

## 1. 做了什麼

給定球現在的位置和速度，預測反彈、最高點、穿越網平面及落桌的時間和球心位置，並辨認撞網、桌外落球與不支援的擦邊情況。這是物理模型預測器，沒有神經網路訓練。碰拍後用實測新球速重新預測，不預知未來球拍的動作。

閱讀順序：[球參數](../../configs/ball.json) → [ball.py](../../src/airbot_tt/ball.py) → [prediction.py](../../src/airbot_tt/prediction.py) → [tests/prediction.py](../../tests/prediction.py) → [單拍整合測試](../../tests/single_shot.py)。

## 2. 輸入與輸出：先弄清單位和語意

```python
from airbot_tt.prediction import predict_ball

result = predict_ball(
    [-0.8, 0.0, 1.2, 2.8, 0.0, 1.5],
    horizon_s=2.0,
    first_table_event='landing',
)
```

`state=[x,y,z,vx,vy,vz]`，前三項m、後三項m/s。這個例子表示球在己方半場上方，朝對方移動且正在上升。世界X沿桌長、Y沿桌寬、Z向上並從地面起算；原點不在桌面上。

輸出是 `events` 清單，每個事件有 `kind`、`time_s`、`position_m`、`velocity_m_s`，另有 `termination` 和範圍說明。時間從這次輸入狀態起算，位置始終是球心。這個接口目前輸出事件，不是可任意查詢所有未來時刻的完整軌跡。

`first_table_event='bounce'` 代表先預測一次桌面反彈，再繼續到下一次落桌；`'landing'` 適合已知碰拍後狀態，遇下一次桌面接觸便停止。這是呼叫者提供的語意，不是函式自動推斷球賽階段。

輸入檢查拒絕非有限六維狀態、非正或超過10秒的horizon、非零摩擦及球心低於桌面接觸平面的狀態。每次呼叫都重新開始，沒有上一球的隱藏history。

## 3. 飛行方程：位置與速度一起往前算

定義位置向量p、速度v：

```text
dp/dt = v
dv/dt = [0, 0, -g] - (rho * Cd * pi * r² / (2m)) * |v| * v
```

`m=0.0027kg`、`r=0.02m`；rho為空氣密度，Cd為阻力係數。阻力與速度相反，大小隨速度平方增加。使用完整三維速度長度，所以水平阻力也受垂直速度影響，不能把三軸當成獨立的一維運動。

`prediction.py` 的微分方程：

```python
def rhs(t, s):
    return np.r_[
        s[3:],
        drag_force(s[3:], c) / c['mass_kg']
        + [0, 0, -c['gravity_m_s2']],
    ]
```

`s[:3]`是位置，`s[3:]`是速度；回傳前三項是位置變化率，後三項是速度變化率。`np.r_`將它們接成六維向量。`drag_force`只回傳阻力，重力另外加入。仿真與預測共用同一參數和力律，避免仿真質量與預測質量不一致；係數仍未實測標定。

## 4. DOP853積分與PhysX步長是兩回事

```python
sol = solve_ivp(
    rhs, (t0, horizon_s), y,
    method='DOP853', rtol=1e-9, atol=1e-11,
    max_step=.02,
    events=(table, apex, net, net_front),
)
```

SciPy的DOP853依誤差自動調整步長，最大一步20ms；每步更新位置與速度，並在步內求事件函式的零點。20ms不是事件時間解析度。`rtol`／`atol`控制數值積分精度，不是實物誤差保證。

PhysX另以固定480Hz步進，每步約2.083ms；預測器沒有呼叫PhysX來偷看未來。較精細的連續積分仍可能與離散接觸仿真不同，因此必須實測比較。

## 5. 事件如何算出來

| 事件 | 函式過零條件 | 解讀 |
| --- | --- | --- |
| 桌面接觸 | `z-(table_top+radius)=0`，下降方向 | 球底碰桌；球心高度是0.78m，不是桌頂0.76m |
| 最高點 | `vz=0`，由正變負 | 上升轉成下降 |
| 網平面穿越 | `x=0` | 球心穿越中央平面，不等於合法回球 |
| 接近網面 | 球心到來球側網面距離等於半徑 | 再檢查高度和橫向範圍決定是否撞網 |

```python
def table(t, s):
    return s[2] - surface

table.direction = -1
table.terminal = True
```

`direction=-1`只收下降穿越，避免反彈向上離開接觸面又算一次。`terminal=True`先停止這段積分，好在撞桌時改速度。

桌面事件還要檢查X／Y是否在桌內。明確在桌外標 `out_of_table`；距邊界約一個球半徑內標 `unsupported_table_edge`，不拿正面回彈公式冒充擦邊模型。`out_of_table`在這裡是球下降到桌面接觸高度卻不在桌內，不是球最終碰到地面的時間。

網前面位置包括網半厚度與球半徑。初版用 `abs(x)` 偵測，積分一步跨越兩側零點時可能漏掉整張薄網；改成來球側的有符號平面後，左右兩側撞網單元案例都通過。網頂及側緣接觸標不支援；明確撞網後停止，不繼續預測網布或反彈。

## 6. 桌面反彈後重新積分

無摩擦模型只改法向速度：

```python
y = s.copy()
y[5] *= -c['table_restitution']
t0, table_kind = float(time), 'landing'
```

桌面係數目前0.9；若撞前vz=−3m/s，撞後為+2.7m/s，vx／vy不變。再以接觸時刻和更新狀態積分到下一次落桌。`for _ in range(2)`表示最多兩段飛行，不是無限多次反彈。

這是瞬時回彈近似，沒有球殼形變、切向摩擦或旋轉交換。新Sony論文即使討論更複雜模型，也尚未被此程式採用。

## 7. 與單拍場景如何接起來

[shot_scene.py](../../src/airbot_tt/shot_scene.py) 的 `SingleShot.forecast()`把當前實測 `self.state` 傳給預測器。尚未reset時拒絕呼叫。

```text
初始球狀態 → 預測碰拍之前的事件
                   ↓
          PhysX實際碰拍，取得新球速
                   ↓
新球狀態 → first_table_event='landing' → 預測落桌
```

[tests/single_shot.py](../../tests/single_shot.py)先用發球時狀態預測，再用實際接觸切分比較區間。碰拍前預測不應拿來比較撞拍後軌跡；它並不知道未來拍面會改變球速。

M4證明的是「已知球狀態後，能預測它怎麼飛」。M5才要決定怎樣揮拍產生需要的出球狀態；M4沒有控制臂去追球。

## 8. 如何驗證，不用同一套結果自證

### 解析解

[test_prediction.py](../../tests/test_prediction.py)關閉阻力，使用 `z=z0+vz0*t-g*t²/2` 推導最高點、過網和落桌時間，並驗證反彈後飛行、呼叫獨立性、兩側撞網、邊界及非法輸入。

### 獨立PhysX比較

[tests/prediction.py](../../tests/prediction.py)用相同初始狀態，一邊呼叫預測器，一邊讓PhysX獨立步進。測試禁止正常運動直接寫球狀態。從實際接觸力判斷撞桌／撞網，從相鄰實測狀態插值取得apex與網平面穿越，再比較兩份事件清單。

預測器與仿真共用力律與參數，因此這是兩種積分／接觸實作的一致性檢查，不是完全獨立的物理理論驗證，更不是實物標定；解析解測試另行提供公式檢查。

固定驗收集 `m4-events-v1` 包含8個反彈、8個回球飛行、4個撞網和4個桌外案例。事件種類或順序不一致直接FAIL，不只比較成功匹配的事件。每類分別統計：

```python
position_error = np.linalg.norm(predicted_position - measured_position)
time_error = abs(predicted_time - measured_time)
```

每類P95須≤20mm／10ms。P95是有限案例的誤差百分位，不是95%信賴區間，也不是所有真實來球的保證。

### 結果及負結果

240Hz時，反彈後落桌時間P95=11.883ms，超過10ms；整合場景偏球apex位置誤差23.671mm也超20mm。保留相同案例、係數與門檻，改480Hz後通過：

| 事件 | 樣本數 | P95位置 | P95時間 |
| --- | ---: | ---: | ---: |
| 反彈 | 8 | 5.52mm | 2.93ms |
| 最高點 | 16 | 4.50mm | 4.48ms |
| 網平面穿越 | 8 | 3.46mm | 0.14ms |
| 落桌 | 16 | 6.11mm | 5.63ms |
| 撞網 | 4 | 1.55mm | 2.48ms |

同場景M3四組來球，碰拍前／實測碰拍後最大位置誤差6.80mm、時間2.943ms。單拍場景因此採480Hz，控制時間軸、感測更新、球步進和settle都用同一dt；原Foundation仍240Hz。每秒物理步數加倍，並非免費提高精度。
