# M2：讓球的運動先有可信的仿真基線

補充日期：2026-11-16。以下對照目前程式並回顧階段實作；歷史結果不代表本輪重跑驗證。

## 做了什麼

建立40mm／2.7g球、標準桌、剛性球網及靜態CAD拍面，驗證重力飛行、空氣阻力、反彈、拍面撞擊、桌緣、撞網和重現性。此階段先沒有可動手臂，方便分離物理問題。

## 程式如何完成

[ball.py](../../src/airbot_tt/ball.py)計算 `F = -0.5*rho*Cd*pi*r²*|v|*v`。使用完整三維速度長度，阻力方向與速度相反；重力交給PhysX。

[ball_scene.py](../../src/airbot_tt/ball_scene.py)的 `prepare_step()` 讀球速→計算世界阻力→轉成球局部座標→設定外力→寫入物理；`step()` 推進PhysX；`read_step()` 讀位置、速度和接觸力。`reset()` 才允許直接寫球狀態。

球材質恢復係數設為1，和桌／拍面採min combine，使接觸有效係數由表面設定控制。摩擦暫為0，以隔離法向反彈；球網用剛性薄板，不模擬網布變形。

## 怎麼驗證

[ball_physics.py](../../tests/ball_physics.py)用無阻力解析解、獨立DOP853積分及實測接觸／能量比較結果，不只看動畫。`./verify_ball.sh` 以全新程序分別跑240／480／960Hz，再由 [check_ball_convergence.py](../../tests/check_ball_convergence.py)比較。活躍SimulationContext內改dt曾卡住，因此每個頻率建立新程序。

歷史限定測試相鄰步長最大落點差6.764mm、速度差0.601%，通過10mm／2%門檻。單一整拍凸包產生假側速是這階段的重要負結果：先用靜態CAD三角面建立參考，M3再修正可動拍碰撞。

## 原理與限制

- **施力前先確認座標系**

  阻力與球的運動方向相反，大小隨速度平方增加。我們用世界座標計算阻力，但本機 Isaac Lab 2.1 的外力接口接受球的局部座標，因此要先做轉換。檢查方法是旋轉球的初始姿態：相同來球速度下，飛行軌跡應保持一致。

- **正常運動要靠驅動或施力，不能直接改位置**

  直接寫入關節角或球的位置，適合初始化與重置。正常運動若也這樣做，就可能跳過慣性、追蹤誤差與碰撞反應。因此手臂透過關節驅動運動，球則交給重力、阻力和接觸力推動。

- **步長收斂不等於實物準確**

  步長越小，仿真計算通常越細，但也越慢。我們比較了 240／480／960 Hz，限定測試中最大落點差約 6.8 mm、出球速度差約 0.6%，已通過門檻。這表示數值結果夠穩定；球拍回彈、摩擦等係數仍未實測校準，不能據此認定真實擊球也同樣準確。

## 展開：從速度算外力，再交給PhysX

[ball.py](../../src/airbot_tt/ball.py)的力律等價於：

```python
scale = 0.5 * rho * Cd * np.pi * radius**2
force_world = -scale * np.linalg.norm(velocity_world) * velocity_world
```

速度加倍，阻力大小變四倍；v為零時F為零，且 `F dot v <= 0`，表示阻力不會主動加能量。[test_ball.py](../../tests/test_ball.py)測零值、平方縮放、耗散及方向，這些比單純比對一個輸出數字更能發現實作錯誤。

Lab2.1外力接口接受剛體局部座標，因此 `prepare_step()` 還要做：

```python
force_body = quat_rotate_inverse(ball.data.root_quat_w, force_world)
ball.set_external_force_and_torque(force_body, zero_torque)
ball.write_data_to_sim()
```

這是省略tensor維度的流程示意。逆四元數旋轉把世界向量轉到球的局部座標；否則球姿態一變，阻力在世界中的方向也跟著錯轉。測試用相同位置／速度、不同初始四元數比較軌跡，應一致。正常步進先施力後step再update；只改球的顯示位置會繞過動力學。

## 接觸參數如何作用，不是直接寫反彈速度

M2的實際反彈交給PhysX。球材料e=1，桌e=0.9、拍e=0.8、網e=0，combine mode=min；在這組設定下 `min(e_ball,e_surface)` 決定對應係數。摩擦為0，沒有切向耗散或旋轉交換。這是用來分離法向物理的基線，不是橡膠／球網的實測材料模型。

球和scene啟用CCD以減少高速球一步穿過薄物體的風險，但CCD不保證任意速度與幾何都可靠。版本沒有直接提供某個便利設定時，用原生USD PhysxRigidBodyAPI設定body CCD；未因此升級Isaac或混用新版API。

## 逐項驗證怎麼看

| 案例 | 獨立比較或測量 | 暴露的問題 |
| --- | --- | --- |
| 無阻力飛行 | `p=p0+v0*t+0.5*g*t²`、`v=v0+g*t` | 重力方向、時間、狀態更新錯誤 |
| 有阻力飛行 | 測試內另寫三維RHS，以DOP853積分 | 生產力律、施力座標或積分偏差 |
| 垂直撞桌 | 接觸力起始、撞前／後vz，計算回彈比 | 實際質量／材質和設定不一致 |
| 正面撞拍 | 法向回彈、側向速度、能量及後續落點 | 拍面法線錯、假斜面或不合理加能 |
| 撞網／桌外 | 真實接觸與無接觸案例 | 穿透或不存在的碰撞面 |
| 重置 | 重複相同初始狀態比對整段軌跡與力 | 殘留速度、外力或感測history |

接觸事件是離散步的量測，撞前一步速度與瞬間接觸速度略不同，所以恢復係數測試容許有限數值差。靜止拍不得不合理加能；這一條不能原封不動拿去限制移動拍，因為移動拍可以透過驅動對球做功。

## 三頻率收斂如何避免「舊報告也算通過」

[check_ball_convergence.py](../../tests/check_ball_convergence.py)不只讀PASS字樣，還檢查三份報告process exit code=0、run token不同，以及參數、source SHA、commit、網格和裝置一致。確認dt依序是1/240、1/480、1/960秒，才比較：

```text
速度相對差 = |v_coarse - v_fine| / |v_fine| <= 2%
接觸時間差 <= 2 * coarse_dt
落點平面距離差 <= 10mm
```

這些通過表示對限定案例縮小步長時結果趨近，不表示連續解完全正確。M4後來以更嚴格事件時間比較發現240Hz不足，改480Hz；這不是推翻M2，而是驗收問題和精度需求不同。
