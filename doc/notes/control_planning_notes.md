# 擊球控制研究：前置理解與後續限制

## 要解決什麼

M4回答球會去哪裡；M5要決定擊球時刻、拍面位置／方向與速度，並讓手臂實際完成。這頁保留實作前的研究理解；本次已實作內容與驗證請讀 [M5筆記](m5.md)，在線重規劃等限制仍未解決。

## 程式要接在哪裡

現有 [prediction.py](../../src/airbot_tt/prediction.py)提供球事件，[kinematics.py](../../src/airbot_tt/kinematics.py)提供FK／IK／Jacobian，[trajectory.py](../../src/airbot_tt/trajectory.py)目前以rest-to-rest為主。需先補非零擊球速度及擊球後減速，再由 [runtime.py](../../src/airbot_tt/runtime.py)驅動並量測真實paddle運動。

## 完成順序與驗證界線

來源與接口核對→正式測試前訂定門檻→無球揮拍跟蹤→可動拍撞球→凍結驗證集評估回球率。Ruckig、HITTER等只作候選研究，不因收錄而引入依賴；原80%合法回球驗收保持。具體活動待辦維持於本地唯一PLAN。

- **軌跡生成不等於擊球控制完成**

  Ruckig支援非零目標速度，但還須驗證指定時刻能否到位、關節限位、碰撞及實際拍面速度。Community中間路點依賴雲端，不能直接當成本地即時方案。

- **先把揮拍控制驗清楚，再看回球率**

  M5先無球量測指定時刻的拍面位置、方向和速度，再測移動球拍撞球，最後評估完整回球。這樣失敗時才能分辨是手臂沒跟上、碰撞模型不準，還是擊球方案本身不對；靜態拍通過不代表高速揮拍也通過。
